AI BACKEND (cloud APIs, NOT local LLM):
- Multi-provider: Groq (free, default), Claude Haiku, Gemini Flash
- User switches provider from app Settings screen
- Originally planned local LLM (Phi-3 Mini/Llama 3.2) but pivoted
  to cloud APIs due to RAM constraints on test hardware
- STT: OpenAI Whisper (CPU mode — forced via
  os.environ["CUDA_VISIBLE_DEVICES"] = "" because RTX 5060 uses
  sm_120 architecture not yet supported by stable PyTorch)
- TTS: pyttsx3 — MUST create a fresh engine instance per speak()
  call (engine = pyttsx3.init() inside the function, not global)
  or it throws "run loop already started" after first call.
  NOTE (2026-06-26 audit): speak() already uses fresh init per call,
  BUT init_tts() still runs at startup and keeps a global tts_engine —
  likely why the bug persisted. Full fix = remove global init_tts()
  and tts_engine entirely, not only patch speak().

=================================================
KNOWN ISSUES / IN-PROGRESS BUGS
=================================================
1. TTS STOPS WORKING AFTER FIRST RESPONSE
   Symptom: "TTS error: run loop already started" on every
   message after the first. Root cause: pyttsx3 engine reuse.
   speak() already creates fresh pyttsx3.init() per call, BUT
   init_tts() still runs at startup (line ~622) and sets global
   tts_engine — remove init_tts(), global tts_engine, and the
   startup call; keep only per-call init inside speak().

2. RESPONSES SOUND ROBOTIC
   Cause: SYSTEM_PROMPT enforces "ONE sentence only, max 15 words,
   never roleplay" — too rigid for natural conversation. Needs
   rewriting to allow warmer, more human phrasing while still
   being reasonably concise (not paragraphs, just not robotic
   one-liners like "I am functioning within optimal parameters").

3. SPOTIFY COMPLETELY NON-FUNCTIONAL
   Root cause: Settings screen only has a Switch toggle for
   "Spotify account" — this ONLY sets a local boolean
   (setSpotifyLinked), it does NOT perform real OAuth. There is
   no actual login flow wired up. spotifyService.ts has
   getAuthUrl() and exchangeCode() functions but nothing in the
   UI calls them or handles the redirect callback.
   ALSO: Spotify CLIENT_ID and CLIENT_SECRET are still placeholders.
   FIX NEEDED: Add keys, then build real OAuth flow — open getAuthUrl()
   in a browser/WebView, handle jarvis://callback deep link,
   extract the code param, call exchangeCode(code), THEN set
   linked=true. isAuthenticated() always false because accessToken
   is never set. Dashboard "Not playing" is a symptom of this.

4. BLE PROVISIONING CRASHES IN EXPO GO
   react-native-ble-plx is a native module, not supported in
   Expo Go. DECISION: skip via Skip button for now; no EAS build
   until user asks.

5. expo-battery import error
   Fixed by running: npx expo install expo-battery
   (package is in package.json — confirmed installed)

6. Gemini provider sometimes returns "Gemini had an issue, try
   again!" — key is set on server; test with groq first to isolate.
   If Gemini-only, key format or API quota may be the issue.

7. API KEYS: News, Spotify, and Google Calendar OAuth keys received from user
   (not yet in code files). Anthropic skipped — use Groq/Gemini only for now.
